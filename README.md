# OSM Feature Picker (QGIS プラグイン)

緯度経度で指定した範囲のOpenStreetMap地物をOverpass API経由でダウンロードし、
QGISの地図上にレイヤとして表示するプラグインです。

## インストール

すでに以下のフォルダにコピー済みです（QGISのデフォルトプロファイル）。

```
~/Library/Application Support/QGIS/QGIS3/profiles/default/python/plugins/osm_feature_picker/
```

QGISを起動し、`プラグイン` → `プラグインの管理とインストール` → `インストール済み` タブで
`OSM Feature Picker` にチェックを入れて有効化してください。有効化するとツールバーと
`プラグイン` メニューにアイコンが追加されます。

コードを修正した場合は、`qgis_osm_feature_picker/osm_feature_picker/` フォルダの内容を
上記インストール先に上書きコピーし、QGISで `Plugin Reloader` プラグイン等を使うか
QGISを再起動して反映してください。

## 使い方

1. ツールバーの `OSM Feature Picker` アイコンをクリックしてダイアログを開く。
2. 「範囲」で south/west/north/east の緯度経度を入力するか、地図を目的の範囲に
   ズームしてから「現在の地図表示範囲を使用」を押す。
   - 矩形ではなく任意形状のポリゴン（行政界・海岸線に沿った範囲など）で範囲を
     指定したい場合は、「任意形状のポリゴンから範囲指定」でポリゴンレイヤを
     選び、「このポリゴンから範囲を設定」を押す。選択中のレイヤに選択地物が
     あればその形状を、なければレイヤの全地物の形状を範囲として使用し、south/
     west/north/east欄にはそのポリゴンの外接矩形が自動入力される。取得時に
     広い範囲で自動タイル分割が発生する場合は、**ポリゴンと重ならないタイルは
     自動的に除外**され、Overpassへの無駄な問い合わせを避けられる（ポリゴンの
     形状自体で地物を絞り込むわけではなく、あくまでどのタイルを取得するかの
     判定に使われる点に注意）。south/west/north/eastの数値を直接編集したり
     「現在の地図表示範囲を使用」を押すと、設定したポリゴンは解除され通常の
     矩形範囲指定に戻る。
3. 「タグフィルタ」テーブルにOSMタグを入力する（キー列・値列は幅固定）。
   - キー欄に文字を入力すると、taginfo.openstreetmap.org由来のよく使われる
     OSMキー（約3000件）の中から、入力した文字列を含む候補が入力中に
     ポップアップ表示されます。
   - どんなキーがあるか分からない場合は、キー列の下にある
     「この範囲のキー候補を取得...」を押すと、指定した範囲に実際に存在する
     タグ付き地物からキーを集計し、出現件数・説明文とともに一覧表示します
     （絞り込み検索も可能）。説明文（OSM Wikiの内容をtaginfo経由で取得、
     日本語があれば日本語・なければ英語）はバックグラウンドで順次取得され、
     列に表示されるとともにカーソルを合わせるとツールチップでも確認できます。
     一覧から選んで「選択したキーをタグフィルタに追加」を押すか、行を
     ダブルクリックすると、そのキーがタグフィルタの新しい行に追加されます。
   - 同じ範囲・同じ要素（ノード/ウェイ/リレーション）でもう一度
     「この範囲のキー候補を取得...」を押した場合は、Overpassへ再取得せず
     前回の結果をそのまま表示します（取得済みの説明文もキャッシュされ、
     再取得されません）。範囲や要素を変えた場合は自動的に再取得されます。
   - キーを入力したら、その行を選択した状態で「選択行の値候補を取得...」を押すと、
     同様にその範囲・そのキーに実際に存在する値を出現件数順に一覧表示します。
     選ぶとその行の「値」欄に反映されます。
   - 例: キー `building` / 値 空欄 → 建物をすべて取得
   - 例: キー `amenity` / 値 `cafe` → カフェのみ取得
   - 行は複数追加可能（OR条件として全て取得されます）
4. 取得する要素（ノード/ウェイ/リレーション）を選択（デフォルト全て）。
5. 「範囲分割時の設定」で、タイル分割が発生した場合にタイルごとに空ける待機時間
   （秒）を指定できます。既定値は3600秒（1時間）です。Overpassサーバー側の
   レート制限・クエリの優先度低下を避けるため、広い範囲を分割取得する際は
   タイル同士の間隔を十分に空けることを推奨します。
6. 「ダウンロード」を押す。Overpass APIに問い合わせ、該当する地物を
   `points` / `lines` / `multilinestrings` / `multipolygons` / `other_relations`
   のレイヤとしてQGISに読み込みます（データがある種類のみ追加されます）。
   - 範囲が広い場合（1辺あたり約0.05度、緯度によりますが5km前後を超える場合）は、
     自動的に負荷の低い格子状のタイルに分割します。分割が発生する場合は開始前に
     確認ダイアログが表示され、タイル数と待機時間だけでのおおよその所要時間
     （長い場合は分・時間単位で表示）が分かります。
   - **タイルごとの逐次レイヤ化**: 分割取得の場合、全タイルの結果を結合してから
     まとめてレイヤ化するのではなく、**1タイル取得できるたびに、その場でQGISレイヤ
     として追加**します（`OSM_1_tile3_points`のようにタイル番号を含むレイヤ名）。
     途中で失敗・キャンセルしても、それまでに成功した分はすでにレイヤとして
     残ります。
   - **タイル境界レイヤ**: ダウンロード開始と同時に、全タイルの境界を表すポリゴン
     レイヤ（`OSM_1_tiles`など）が作成されます。各ポリゴンには取得データと同じ
     `tile_id`（タイル番号）と、状態を表す`status`列
     （`pending`=未処理 / `success`=取得成功 / `empty`=取得成功だが該当地物なし /
     `failed`=再試行しても失敗）が入ります。地図上でどのタイルが失敗したか
     一目で確認でき、失敗した範囲だけを「範囲」欄に入力して再実行することで、
     再取得のコストを抑えられます。
   - 一部のタイルの取得が失敗した場合は、間隔を空けて自動的に最大2回まで再試行
     します（再試行のたびにOverpassへ要求するタイムアウト値も伸ばします）。
     それでも失敗したタイルは`failed`のままスキップし、残りのタイルの取得を
     続行します。
   - タイル分割時のダウンロードはバックグラウンドスレッドで実行されるため、
     待機時間を長く設定してもQGIS自体はフリーズせず、他の作業を続けられます。
     実行中は「キャンセル」ボタンで途中停止できます（処理中のタイルが完了し
     次第、数秒以内に停止します）。ダイアログを閉じようとした場合も、実行中で
     あれば確認のうえ停止します。
   - この分割・間隔取得は「この範囲のキー候補を取得」「選択行の値候補を取得」でも
     同様に働きますが、これらは（QGIS地物化を伴わないため）従来どおり全タイルの
     結果をまとめてから一覧表示する方式のままです。
7. 読み込まれたレイヤは通常のQGISレイヤなので、QGIS標準の「地物を選択」ツールでの
   選択や、右クリック `エクスポート` → `地物の保存` でのGeoPackage/Shapefile等への
   保存など、QGISの機能をそのまま利用できます。

## 技術メモ

- ダウンロードが複数タイルに分割される場合、[tiled_download_worker.py](osm_feature_picker/tiled_download_worker.py)
  の`TiledDownloadWorker`（バックグラウンドQThread）がタイルを1つずつ取得し、
  完了ごとに`tile_finished`シグナルでメインスレッドに通知します。メインスレッド側
  （[osm_feature_picker_dialog.py](osm_feature_picker/osm_feature_picker_dialog.py)の
  `_on_tile_finished`）がそのタイルのデータをすぐにQGISレイヤ化し、
  [osm_layers.py](osm_feature_picker/osm_layers.py)の`create_tile_grid_layer`/
  `set_tile_status`でタイル境界レイヤの該当ポリゴンの状態を更新します。
  QGISオブジェクトの操作は必ずメインスレッド側（シグナルのスロット）で行い、
  ワーカースレッド側はネットワーク通信と待機のみを行います。
- 説明文をバックグラウンドで取得するスレッドは、ダイアログを閉じる際に必ず
  停止(または安全に切り離し)を待ってから破棄されます
  ([candidate_list_dialog.py](osm_feature_picker/candidate_list_dialog.py)の
  `_stop_worker`)。これを怠ると、通信中にスレッドオブジェクトが破棄されて
  QGISが異常終了(abort)する場合があったため対応しています。タイル分割
  ダウンロードの`TiledDownloadWorker`も同様に、ダイアログを閉じる際は
  （実行中であれば確認のうえ）`_stop_download_worker`で安全に停止・切り離しを
  行います。「キャンセル」ボタンでの中断時は、待機ループが1秒おきに停止要求を
  確認するため、長い待機時間を設定していても数秒以内に停止します。
- データ取得は Overpass API (`https://overpass-api.de/api/interpreter`) にPOSTしています。
- 取得したOSM XMLはGDAL/OGRの `OSM` ドライバで読み込んでいます。指定したタグキーは
  一時生成する `osmconf.ini`（`resources/osmconf_template.ini` を元に生成）に追記し、
  属性列として展開されるようにしています（デフォルト設定では一部のタグしか
  列にならず、`other_tags` にhstore形式でまとめられてしまうため）。
- 広い範囲は[overpass_client.py](osm_feature_picker/overpass_client.py)の`split_bbox`で
  格子状のタイル（既定で1辺あたり最大0.05度）に自動分割し、`fetch_tiled`が
  タイルごとに間隔（既定3秒、`DEFAULT_TILE_DELAY_SECONDS`）を空けて順に取得します。
  タイル境界をまたぐ地物は複数タイルに重複して現れるため、`(要素種別, id)`単位で
  重複排除してからマージ・出力します。1タイルが取得しきれない場合は間隔を空けて
  最大2回まで自動再試行し（`DEFAULT_TILE_RETRIES`/`DEFAULT_TILE_RETRY_BACKOFF_SECONDS`）、
  それでも失敗すればそのタイルだけスキップして残りを続行します（全滅した場合のみ
  エラーになります）。
- Overpassはクエリが内部タイムアウト（`[timeout:N]`）に達すると、HTTPエラーには
  ならずに`<remark>`要素（タイムアウト警告）付きの**不完全な**応答を返すことが
  あります。この応答にはway/relationのタグだけが含まれ、形状を作るための
  `<node>`座標データが丸ごと欠落しているため、GDALがジオメトリを解決できず、
  取得自体は「成功」扱いなのに地物が1件も読み込まれないという問題がありました。
  このため`_post`で`<remark>`（JSON応答では`"remark"`）の有無を検査し、含まれて
  いれば失敗として扱うようにしました。さらに、タイルの再試行のたびに要求する
  タイムアウト値を大きくしていきます（既定60秒→120秒→180秒）。データ量が多く
  処理に時間がかかるタイル（水域・森林など密なポリゴンが多い地域）でも、
  再試行で完全な応答を得られるようにするためです。
- Overpassから取得したOSM XMLは、GDALのOSMドライバに渡す前に`<node>`要素を
  id昇順に並べ替えています（`overpass_client.py`の`_merge_and_sort_osm_xml`）。
  Overpassの応答は「直接マッチした地物」→「再帰取得した補完ノード」の順で出力
  されるためid順になっておらず、GDAL側の既定インデックスがノード座標を正しく
  解決できず、大きな面地物(森林・水域など)が無条件で欠落することがあったための
  対策です（単純な点地物は影響を受けません）。
- 公式インスタンス(overpass-api.de)が混雑して504等のエラーを返す場合に備えて、
  同じクラスタの負荷分散先である`lz4.overpass-api.de`へ自動フォールバックします
  （`DEFAULT_ENDPOINTS`）。全て失敗した場合のみエラーダイアログが表示されます。
  タイル分割時は、一度成功したサーバーをそのタイル取得の残りでも優先して使う
  （sticky）ことで、1回の取得の中で異なるミラー（同期状況が微妙に異なりうる）が
  タイルごとに混在しないようにしています。
  - 過去に`overpass.osm.ch`もフォールバック先に含めていましたが、HTTPエラーを
    返さず「形式的には正しいが実質空」の応答（異常な`osm_base`値）を返すことが
    判明したため削除しました。この種の壊れた/信頼できないミラーを将来的にも
    検知できるよう、応答に含まれる`osm_base`のタイムスタンプ形式を検証し、
    不正な場合はエラー扱いにして次のサーバーへフォールバックするようにしています。
- Overpass APIの利用規約・使用制限（頻繁な大量リクエストの禁止など）に従ってください。
  範囲分割が発生する場合は開始前に確認ダイアログが表示されます。
- ポリゴンレイヤから範囲を設定した場合、[osm_layers.py](osm_feature_picker/osm_layers.py)の
  `filter_tiles_by_geometry`で、`split_bbox`が作った矩形タイルのうち指定ポリゴンと
  交差しないものを取得対象から除外します（ポリゴンが他のCRSのレイヤに由来する場合は
  WGS84へ変換してから判定）。除外後にタイルが1つだけになった場合は、タイル分割せず
  そのタイル（元の外接矩形全体ではなく）の範囲のみでOverpassへ問い合わせます。
  Overpassへのクエリ自体は矩形のbboxフィルタのままで、ポリゴンの形状で地物を
  クリップして取得しているわけではない点に注意してください。

## 動作確認

Overpass APIへの疎通、OGR OSMドライバでの読み込みまでの一連の処理は、QGIS付属の
Python (`QGIS.app/Contents/MacOS/python3.12`) を使ったヘッドレステストで動作確認
済みです。ダイアログのUI操作自体（クリック等）は実際のQGIS上でご確認ください。

範囲の自動分割・間隔取得（タイリング）については、タイル分割ロジック・
重複排除ロジックを合成データによるユニットテストで検証し、実データでも
GDAL純正ツール(ogrinfo)とQGIS読み込みの件数一致、分割取得での実在施設
データの正常な取得を確認済みです。分割あり/なしでの地物数完全一致という
最終的なエンドツーエンド比較は、その後45タイル規模の範囲（実際にユーザーが
「地物が見つからない」と報告した範囲）で実施し、分割取得側でも2000件を超える
実データ（水域ポリゴン）が正しく取得・マージされることを確認しました。

その調査の過程で、Overpassのクエリが内部タイムアウトした際に「HTTPは成功
だが地物のタグだけあって座標データが丸ごと欠落した」応答が返ることがあり、
これが「取得は成功したのに地物が0件」という不具合の原因であることを特定し、
`<remark>`タイムアウト警告の検知とタイムアウト値を伸ばしながらの再試行で
対策済みです（合成データによるテストで、切り詰められた応答→再試行→完全な
応答の取得、という流れを確認済み）。実際の使用で結果に疑問がある場合は、
範囲を狭めて「現在の地図表示範囲を使用」からやり直すか、時間をおいて
再試行してください。

さらに、`split_bbox`の分割数計算が浮動小数点の誤差でまれに想定より1行/1列
多くタイルを作ってしまう問題を発見・修正しました（許容誤差を設けて対応）。

タイルごとの逐次レイヤ化・タイル境界レイヤ・キャンセル機能については、
モックしたネットワーク応答を使ったテストで以下を確認済みです。
- 成功/空/失敗の3パターンが混在するタイル群に対し、成功・空のタイルはそれぞれ
  正しい`tile_id`でレイヤ化され、タイル境界レイヤの`status`列が
  success/empty/failedそれぞれ正しく反映されること
- 「キャンセル」を押すと（待機時間を長く設定していても）1秒程度でワーカーが
  停止し、ダイアログの状態（ボタンの有効/無効、キャンセルボタンの表示）が
  正しく復帰すること
- ダウンロード実行中にダイアログを閉じても（確認ダイアログで続行を選んだ場合）
  実行中のバックグラウンドスレッドが安全に停止・切り離しされ、QGISが
  異常終了しないこと

任意形状のポリゴンからの範囲指定については、以下をヘッドレステストで確認済みです。
- `filter_tiles_by_geometry`が、ポリゴンと交差しないタイルのみを正しく除外すること
- ポリゴンレイヤ（選択地物があればその形状、なければ全地物）から外接矩形が
  south/west/north/east欄に正しく設定され、ポリゴン形状が内部に保持されること
- south/west/north/eastを直接編集する、または「現在の地図表示範囲を使用」を押すと
  保持していたポリゴン形状が解除されること
- ポリゴン設定後にダウンロードすると、除外後に1タイルだけ残るケースでは
  ポリゴンの外接矩形全体ではなく、そのタイル自身の（より狭い）矩形でOverpassに
  問い合わせること

## 公式リポジトリへの公開手順

1. 公開用のGitHubリポジトリを作成し、このフォルダの内容をpushする（`metadata.txt`の
   `repository` / `tracker` / `homepage` にURLを記入する。公式リポジトリでは
   `repository` と `tracker` が必須）。
2. `dist/osm_feature_picker-<version>.zip` を作成する（`__pycache__` や `._*` を含めない）:
   `zip -r dist/osm_feature_picker-0.1.0.zip osm_feature_picker -x "*/__pycache__/*" "*/._*"`
3. https://plugins.qgis.org/ にOSGeo IDでログインし、`Plugins` → `Upload a plugin` からzipをアップロードする。
4. 審査（承認）後に公開される。更新時は `metadata.txt` の `version` を上げて再アップロードする。
